
# Ordinamento e Algoritmi di Sorting

> [!info] Sintesi
> Questa nota raccoglie la teoria e l'analisi algoritmica riguardante i principali **[[Algoritmo di Ordinamento|algoritmi di ordinamento]]**. Vengono analizzati gli algoritmi basati su confronti che utilizzano il paradigma **[[Divide-and-Conquer]]** (come **[[MergeSort]]** e **[[QuickSort]]** nelle varianti deterministica e probabilistica) e **[[InsertionSort]]** (con l'analisi fine basata sulle inversioni), il teorema del **[[Lower Bound]]** mediante **[[Albero di Decisione]]** ($\Omega(n \log n)$), e gli algoritmi non basati su confronti ad alte prestazioni quali **[[BucketSort]]** e **[[RadixSort]]** con il concetto di **[[Ordinamento Stabile]]**.

---

## 1. Specifica Generale del Problema dell'Ordinamento

### Definizione del Problema Computazionale
Il **[[Problema dell'Ordinamento]]** prende in input una sequenza di $n$ chiavi appartenenti a un universo totalmente ordinato e restituisce la medesima sequenza riorganizzata in ordine non decrescente.

- **[[Dominio delle Istanze]] ($I$):** Insieme di tutte le sequenze $S = (S[0], S[1], \dots, S[n-1])$ di $n \ge 0$ chiavi.
- **[[Dominio delle Soluzioni]] ($S$):** Insieme di tutte le sequenze $\bar{S}$ di $n$ chiavi ordinate in senso crescente.
- **Relazione Computazionale ($\Pi \subset I \times S$):** $\bar{S}$ contiene le stesse chiavi di $S$, con le medesime eventuali ripetizioni, tali che:
$$
\bar{S}[0] \le \bar{S}[1] \le \dots \le \bar{S}[n-1]
$$

---

## 2. Algoritmi Basati su Confronti (Comparison-Based Sorting)

Un algoritmo si dice **basato su confronti** se l'ordinamento relativo delle chiavi per qualsiasi istanza di input è determinato **esclusivamente** dai confronti tra coppie di chiavi
($S[i] \le S[j]$ o $S[i] \ge S[j]$).

---

### Il Paradigma Divide-and-Conquer
Molti algoritmi basati su confronti utilizzano il pattern di progettazione **[[Divide-and-Conquer]]**, articolato in 3 fasi:
1. **Divide:** Suddivisione dell'istanza di taglia $n$ in sotto-istanze di taglia inferiore.
2. **Conquer:** Risoluzione ricorsiva delle sotto-istanze (fino al raggiungimento dei casi base, risolti direttamente in $O(1)$).
3. **Combine:** Combinazione delle soluzioni delle sotto-istanze per ricostruire la soluzione dell'istanza di partenza.

---

### MergeSort

#### Descrizione e Funzionamento
**[[MergeSort]]** è un algoritmo ricorsivo che applica il paradigma [[Divide-and-Conquer]]:
- **Divide:** Divide la sequenza $S$ di $n$ elementi in due sottosequenze $S_1$ (con $\lceil n/2 \rceil$ elementi) e $S_2$ (con $\lfloor n/2 \rfloor$ elementi).
- **Conquer:** Ordina ricorsivamente le due sottosequenze $S_1$ e $S_2$.
- **Combine:** Unisce le due sottosequenze ordinate $S_1$ e $S_2$ tramite la procedura **`Merge`** producendo la sequenza finale ordinata.

#### Pseudocodice

```python
def merge_sort(S):
    n = len(S)
    if n <= 1:
        return S
    
    # Divide
    mid = (n + 1) // 2
    S1 = S[:mid]
    S2 = S[mid:]
    
    # Conquer
    S1 = merge_sort(S1)
    S2 = merge_sort(S2)
    
    # Combine
    return merge(S1, S2)

def merge(S1, S2):
    S = []
    i = j = 0
    while i < len(S1) and j < len(S2):
        if S1[i] <= S2[j]:
            S.append(S1[i])
            i += 1
        else:
            S.append(S2[j])
            j += 1
            
    # Copia degli elementi rimanenti
    while i < len(S1):
        S.append(S1[i])
        i += 1
    while j < len(S2):
        S.append(S2[j])
        j += 1
        
    return S
```

#### Analisi della Complessità di MergeSort
L'algoritmo `Merge` esegue una sola scansione delle sottosequenze eseguendo un numero di confronti limitato da $|S_1| + |S_2|$, con **[[Complessità Computazionale|complessità]] $\Theta(n)$**.

Sfruttando l'**[[Albero della Ricorsione]]**:
- L'altezza dell'albero della ricorsione è $d = \lceil \log_2 n \rceil = \Theta(\log n)$.
- Ogni livello $i$ dell'albero (con $0 \le i \le d$) contiene $2^i$ nodi, ciascuno operante su sottosequenze di dimensione circa $n / 2^i$.
- Il lavoro complessivo svolto da ciascun livello dell'albero è $\Theta(n)$.

Sommando i costi su tutti i livelli:
$$
T(n) = \sum_{i=0}^{\Theta(\log n)} \Theta(n) = \Theta(n \log n)
$$

**Prestazioni:** $\Theta(n \log n)$ sia al caso migliore, medio che pessimo.

### QuickSort

#### Descrizione e Strategia
**[[QuickSort]]** è un algoritmo ricorsivo [[Divide-and-Conquer]] in-place che seleziona un elemento detto **[[Pivot]]** ($p$) e partiziona la sequenza in tre sottosequenze:
- $L$: chiavi $< p$
- $E$: chiavi $= p$
- $G$: chiavi $> p$

#### Algoritmo Determinista e In-Place (`QuickSortInPlace`)

```python
def quicksort_in_place(S, a, b):
    if a >= b:
        return
    
    # Divide e Partizionamento
    l = partition(S, a, b)
    
    # Conquer
    quicksort_in_place(S, a, l - 1)
    quicksort_in_place(S, l + 1, b)

def partition(S, a, b):
    p = S[b]  # Scelta del pivot (ultimo elemento)
    l = a
    r = b - 1
    
    while l <= r:
        while l <= r and S[l] <= p:
            l += 1
        while l <= r and S[r] >= p:
            r -= 1
        if l < r:
            S[l], S[r] = S[r], S[l]
            
    S[l], S[b] = S[b], S[l]  # Riposizionamento del pivot
    return l
```

> [!abstract] Invariante di Ciclo per `Partition`
> Al termine di ciascuna iterazione del ciclo `while` esterno di `Partition(S, a, b)`:
> 1. $S[j] \le p$ per ogni $a \le j < l$.
> 2. $S[j] \ge p$ per ogni $r < j \le b - 1$.
> 3. $l \le r + 1$.
>
> Questo garantisce che la procedura `Partition` abbia complessità **$\Theta(b - a + 1)$**, ovvero lineare nella dimensione della sottosequenza.

#### Complessità al Caso Pessimo e Caso Migliore
- **Caso Migliore / Medio:** Il pivot divide la sequenza in due parti bilanciate. L'altezza dell'albero della ricorsione è $O(\log n)$ $\implies \mathbf{O(n \log n)}$.
- **Caso Pessimo:** Se l'input è già ordinato (o quasi), la procedura `Partition` isola un solo elemento alla volta (sbilanciamento estremo). L'albero della ricorsione ha altezza $n-1$, generando una sommatoria aritmetica:
$$
T(n) = \sum_{i=0}^{n-1} O(n - i) = \Theta(n^2)
$$

### Algoritmi Deterministici vs Probabilistici: Randomized QuickSort

- **[[Algoritmo Deterministico]]:** Per ogni istanza esiste una e una sola sequenza di operazioni. La complessità al caso pessimo è determinata dall'istanza peggiore.
- **[[Algoritmo Probabilistico]]:** Le scelte dell'algoritmo dipendono da variabili casuali. Per una stessa istanza esistono molteplici esecuzioni possibili.

#### Randomized QuickSort
In **[[Randomized QuickSort]]**, il pivot viene scelto in modo uniformemente casuale nell'intervallo $[a, b]$:

```python
import random

def randomized_partition(S, a, b):
    i = random.randint(a, b)
    S[i], S[b] = S[b], S[i]  # Scambio del pivot casuale con l'ultimo elemento
    return partition(S, a, b)
```

> [!success] Complessità in Alta Probabilità
> **Lemma:** Per qualsiasi istanza di taglia $n$, almeno una frazione $(1 - 1/n)$ delle possibili esecuzioni di `Randomized QuickSort` genera un albero della ricorsione di altezza $O(\log n)$.
> 
> Di conseguenza, `Randomized QuickSort` ha complessità **$O(n \log n)$ con alta probabilità** e **in media**, evitando il caso pessimo su qualsiasi istanza di input.

### InsertionSort

#### Pseudocodice
**[[InsertionSort]]** inserisce progressivamente l'elemento corrente `S[i]` nella posizione corretta della sottosequenza già ordinata `S[0...i-1]`.

```python
def insertion_sort(S):
    n = len(S)
    for i in range(1, n):
        current = S[i]
        j = i - 1
        while j >= 0 and S[j] > current:
            S[j + 1] = S[j]
            j -= 1
        S[j + 1] = current
    return S
```

#### Analisi Fine basata sul Numero di Inversioni
> [!abstract] Definizione di Inversione
> Data una sequenza $S$, una **[[Inversione]]** è una coppia di indici $(i, j)$ con $0 \le j < i < n$ tali che $S[j] > S[i]$.

Sia $K$ il numero totale di inversioni presenti nella sequenza $S$:
$$
0 \le K \le \frac{n(n-1)}{2} \in \Theta(n^2)
$$
- **Teorema:** La complessità temporale di `InsertionSort` è **$\mathbf{\Theta(n + K)}$**, dove $n$ è la dimensione della sequenza e $K$ è il numero di inversioni.
- **Conseguenza:** Per sequenze **quasi ordinate** (dove $K = O(n)$), `InsertionSort` è estremamente efficiente ed esegue in tempo **lineare $\Theta(n)$**.

## 3. Limite Inferiore per Algoritmi basati su Confronti (Lower Bound)

### Modello dell'Albero di Decisione (Decision Tree)
Un **[[Albero di Decisione]]** è un albero binario proprio che rappresenta tutti i possibili percorsi di esecuzione di un algoritmo di ordinamento basato su confronti per istanze di taglia $n$:
- **Nodi Interni:** Rappresentano i confronti della forma $S[i] : S[j]$.
- **Foglie:** Rappresentano le $n!$ possibili permutazioni di ordinamento.
- **Altezza $h$ dell'albero:** Rappresenta il numero massimo di confronti effettuati dall'algoritmo nel caso pessimo.

```
                   S[1] : S[2]
                  /           \
            S[1] < S[2]    S[1] > S[2]
               /                 \
          S[2] : S[3]         S[1] : S[3]
            /    \               /    \
         [...]  [...]         [...]  [...]
```

---

### Dimostrazione del Teorema del Lower Bound

> [!danger] Teorema del Lower Bound per l'Ordinamento
> Ogni algoritmo di ordinamento basato su confronti esegue **$\mathbf{\Omega(n \log n)}$** confronti al caso pessimo per ordinare una sequenza di $n$ elementi.

#### Dimostrazione Formale
1. Poiché vi sono $n!$ distinte permutazioni di input, l'albero di decisione deve avere almeno $m = n!$ foglie.
2. Per le proprietà degli alberi binari propri, l'altezza $h$ soddisfa $h \ge \log_2(m) = \log_2(n!)$.
3. Sviluppando il fattoriale:
   $$n! = \prod_{i=1}^{n} i \ge \prod_{i=\lceil n/2 \rceil}^{n} i \ge \left( \frac{n}{2} \right)^{\frac{n}{2}}$$
4. Calcolando il logaritmo:
   $$h \ge \log_2(n!) \ge \log_2 \left( \left( \frac{n}{2} \right)^{\frac{n}{2}} \right) = \frac{n}{2} \log_2 \left( \frac{n}{2} \right) = \frac{n}{2} (\log_2 n - 1) \in \mathbf{\Omega(n \log n)}$$

**Corollario:** Gli algoritmi **[[MergeSort]]**, **[[HeapSort]]** e **[[Randomized QuickSort]]** sono **asintoticamente ottimi**.

---

## 4. Algoritmi Non Basati su Confronti

Superare la barriera $\Omega(n \log n)$ è possibile assumendo vincoli aggiuntivi sull'universo delle chiavi (es. chiavi intere in un intervallo limitato).

---

### BucketSort

#### Principio e Algoritmo
**[[BucketSort]]** assume che le chiavi siano interi nell'intervallo $[0, N-1]$. Utilizza un array $B$ di $N$ code (**bucket**).

```python
def bucket_sort(S, N):
    # Creazione dei bucket
    B = [[] for _ in range(N)]
    
    # Prima scansione: distribuzione nei bucket
    for entry in S:
        k = entry.key
        B[k].append(entry)
        
    # Seconda scansione: ri-assemblaggio ordinato
    S_sorted = []
    for k in range(N):
        while len(B[k]) > 0:
            S_sorted.append(B[k].pop(0))
            
    return S_sorted
```

#### Complessità Computazionale
- Prima scansione: $\Theta(n)$.
- Seconda scansione: $\Theta(n + N)$ (scorrimento dei $N$ bucket ed estrazione di $n$ elementi).
- **Complessità Totale:** **$\mathbf{\Theta(n + N)}$**.
- **Linearità:** Se $N = O(n)$, la complessità diventa **$\Theta(n)$** (tempo lineare).

---

### Stabilità dell'Ordinamento

> [!abstract] Definizione di Ordinamento Stabile
> Un algoritmo di ordinamento si dice **[[Ordinamento Stabile]] (Stable Sort)** se preserva l'ordine relativo originale delle entry aventi la stessa chiave.

- **BucketSort è stabile** grazie alla politica FIFO (First-In, First-Out) con cui gestisce le code dei singoli bucket.

---

### RadixSort

#### Principio di Funzionamento
**[[RadixSort]]** estende il campo di applicazione di BucketSort a chiavi composte da $d$ cifre $C_{d-1}, C_{d-2}, \dots, C_0$ ciascuna compresa nell'intervallo $[0, N-1]$.

L'algoritmo ordina la sequenza eseguendo $d$ passaggi di un ordinamento stabile (**BucketSort**) partendo dalla cifra meno significativa (**LSD - Least Significant Digit**) fino alla cifra più significativa (**MSD**).

```python
def radix_sort(S, d, N):
    # Ordinamento progressivo dalla cifra c_0 alla cifra c_{d-1}
    for i in range(d):
        S = bucket_sort_by_digit(S, digit_index=i, N=N)
    return S
```

> [!note] Invariante di Correttezza per RadixSort
> Al termine dell'iterazione $i$-esima del ciclo `for`, le entry di $S$ sono ordinate in modo lessicografico corretto rispetto alle $i+1$ cifre meno significative delle chiavi.

#### Complessità
Eseguendo $d$ iterazioni di BucketSort di costo $\Theta(n + N)$:
$$T(n) = \mathbf{\Theta(d(n + N))}$$

Se $d = O(1)$ e $N = O(n)$, la complessità finale di `RadixSort` è **$\mathbf{\Theta(n)}$**.

## 6. Esercizi Teorici e Applicativi

### 1. Conteggio delle Inversioni in $O(n \log n)$
Per determinare il numero di inversioni $K$ in una sequenza $S$ di $n$ elementi in tempo $O(n \log n)$, si adatta l'algoritmo **[[MergeSort]]**:
- Durante la fase di `Merge(S1, S2)`, se un elemento viene prelevato dalla sottosequenza destra `S2[j]`, esso forma un'inversione con **tutti gli elementi rimanenti** nella sottosequenza sinistra `S1[i...]`.
- Si aggiunge `len(S1) - i` al contatore globale delle inversioni.

### 2. Fusione di $k$ Sequenze Ordinate
Date $k$ sequenze ordinate ciascuna di dimensione $m$ (dimensione totale $n = k \cdot m$):
- **Approccio Banale (A coppie):** Fondere $S_1$ con $S_2$, poi il risultato con $S_3$, ecc. Richiede tempo $\Theta(k^2 m) = \Theta(k \cdot n)$.
- **Approccio Efficiente (Min-Heap):** Si inserisce la testa di ciascuna delle $k$ sequenze in una [[Coda di Priorità]] (Min-Heap). Ad ogni passo si estrae il minimo e si inserisce l'elemento successivo dalla medesima sequenza.
- **Complessità:** **$O(n \log k)$**.
