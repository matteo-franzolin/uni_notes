# Code di Priorità e Heap

> [!info] Sintesi
> Questa nota tratta l'[[Abstract Data Type|ADT]] **[[Coda di Priorità]] (Priority Queue)**, analizzandone l'interfaccia, le implementazioni elementari tramite liste ed elenchi ordinati/non ordinati, e l'implementazione efficiente basata su **[[Heap]]** (con le relative operazioni di `insert` tramite [[Up-Heap Bubbling]] e `removeMin` tramite [[Down-Heap Bubbling]]). Vengono inoltre approfonditi le strategie di costruzione dell'heap (**Top-down** e **Bottom-up**), l'algoritmo di ordinamento **[[HeapSort]]** (e confronto con [[SelectionSort]] ed [[InsertionSort]]), ed esercizi pratici/algoritmi avanzati per l'estrazione efficiente dei minimi.

---

## 1. Abstract Data Type Coda di Priorità (Priority Queue ADT)

### Definizione e Concetto
Una **[[Coda di Priorità]]** (o *Priority Queue*) è una struttura dati astratta che memorizza una collezione di **[[Entry]]** del tipo $\langle k, v \rangle$, dove:
- $k$ rappresenta la **[[Chiave]]** (Key), appartenente a un insieme dotato di un ordine totale.
- $v$ rappresenta il **[[Valore]]** (Value) associato alla chiave.

Nelle **[[Min-Priority Queue]]**, l'estrazione restituisce sempre l'elemento con la **chiave minima**.  
Nelle **[[Max-Priority Queue]]**, l'estrazione restituisce l'elemento con la **chiave massima**.

---

### Interfaccia dell'ADT Priority Queue
I metodi fondamentali offerti dall'[[Abstract Data Type|ADT]] sono:
- **`size()`**: Restituisce il numero di entry presenti nella coda.
- **`isEmpty()`**: Restituisce `true` se la coda è vuota, `false` altrimenti.
- **`insert(k, v)`**: Inserisce una nuova entry con chiave $k$ e valore $v$ nella coda.
- **`min()`**: Restituisce (senza rimuoverla) un'entry con chiave minima.
- **`removeMin()`**: Rimuove e restituisce un'entry con chiave minima.

#### Il Comparatore
Per gestire ordinamenti personalizzati sulle chiavi, si utilizza un oggetto **[[Comparatore]]** (Comparator) che formalizza la relazione di ordine totale tra chiavi tramite il metodo `compare(k1, k2)`.

---

## 2. Implementazioni Elementari tramite Liste

Una coda di priorità può essere implementata mediante una **[[Lista Doppiamente Concatenata]]** (Doubly Linked List) adottando due approcci complementari:

### 1. Implementazione tramite Lista Non Ordinata
- **`insert(k, v)`**: L'elemento viene inserito in testa o in coda alla lista in tempo costante $O(1)$.
- **`min()`** e **`removeMin()`**: È necessario scorrere l'intera lista per individuare il valore minimo. Richiede tempo lineare $\Theta(n)$.

### 2. Implementazione tramite Lista Ordinata
- **`insert(k, v)`**: Richiede la ricerca della posizione corretta per mantenere la lista ordinata per chiave crescente. Richiede tempo lineare $\Theta(n)$.
- **`min()`** e **`removeMin()`**: L'elemento minimo si trova in testa alla lista e viene estratto in tempo costante $O(1)$.

| Operazione | Lista Non Ordinata | Lista Ordinata | [[Heap]] |
| :--- | :---: | :---: | :---: |
| **`size()`, `isEmpty()`** | $O(1)$ | $O(1)$ | $O(1)$ |
| **`insert(k, v)`** | $O(1)$ | $\Theta(n)$ | $O(\log n)$ |
| **`min()`** | $\Theta(n)$ | $O(1)$ | $O(1)$ |
| **`removeMin()`** | $\Theta(n)$ | $O(1)$ | $O(\log n)$ |

## 3. Implementazione tramite Heap

L'implementazione efficiente della [[Coda di Priorità]] sfrutta un **[[Heap]]** (albero binario completo memorizzato mediante array con [[Level Numbering]]).

### Proprietà dell'Heap
1. **[[Struttura Binaria Completa]]:** L'albero è saturo a tutti i livelli, tranne eventualmente l'ultimo, che è riempito da sinistra a destra.
2. **[[Heap-Order Property]]:** Per ogni nodo $v \neq r$ con padre $u = \text{parent}(v)$, si ha $\text{key}(u) \le \text{key}(v)$.

---

### Inserimento: `insert(k, v)` e Up-Heap Bubbling

L'algoritmo **`insert`** aggiunge la nuova entry mantenendo la struttura e la proprietà dell'heap:

1. Inserisce la nuova entry $e = (k, v)$ nella prima posizione libera disponibile (ovvero in `P[last + 1]`) e incrementa `last`.
2. Ripristina la [[Heap-Order Property]] risalendo l'albero verso la radice tramite la procedura di **[[Up-Heap Bubbling]]**.

#### Algoritmo Pseudo-codice (`insert`)
```python
def insert(P, k, v):
    e = (k, v)
    last += 1
    P[last] = e
    i = last
    
    # Up-heap bubbling
    while i > 1 and P[i // 2].key > P[i].key:
        swap(P[i], P[i // 2])
        i = i // 2
        
    return e
```

- **Invariante di Ciclo:** L'unica coppia padre-figlio che può violare la [[Heap-Order Property]] è quella tra $P[\lfloor i/2 \rfloor]$ e $P[i]$.
- **[[Complessità Computazionale|Complessità]]:** Poiché l'altezza dell'heap è $h = \lfloor \log_2 n \rfloor$, il ciclo esegue al più $h$ iterazioni. Pertanto, il tempo di esecuzione al caso pessimo è **$O(\log n)$**.

---

### Estrazione del Minimo: `removeMin()` e Down-Heap Bubbling

L'algoritmo **`removeMin`** estrae l'elemento in radice (`P[1]`):

1. Salva la entry nella radice `P[1]`.
2. Sostituisce il contenuto della radice con la entry presente nel nodo `P[last]` e decrementa `last`.
3. Ripristina la [[Heap-Order Property]] scendendo verso le foglie tramite la procedura di **[[Down-Heap Bubbling]]**.

#### Algoritmo Pseudo-codice (`removeMin`)
```python
def remove_min(P, last):
    min_entry = P[1]
    P[1] = P[last]
    last -= 1
    i = 1
    
    j = index_min_child(P, i, last)
    
    # Down-heap bubbling
    while 2 * i <= last and P[i].key > P[j].key:
        swap(P[i], P[j])
        i = j
        j = index_min_child(P, i, last)
        
    return min_entry
```

- **Invariante di Ciclo:** Sia $j$ il figlio di $i$ con chiave minima. L'unica violazione della [[Heap-Order Property]] può verificarsi tra il padre $P[i]$ e il figlio $P[j]$.
- **Complessità:** L'algoritmo scende lungo un cammino di lunghezza al più $h = \lfloor \log_2 n \rfloor$. La complessità è **$\Theta(\log n)$** al caso pessimo.

## 4. Costruzione di un Heap (Heapification)

Dato un array $P$ non ordinato contenente $n$ elementi, esistono due approcci principali per trasformarlo in un heap valido:

### 1. Costruzione Top-down (Inserimenti Successivi)
- **Idea:** Esegue $n - 1$ inserimenti successivi applicando l'[[Up-Heap Bubbling]] per ciascun elemento da $j = 2$ fino ad $n$.
- **Algoritmo:**
  ```python
  def build_heap_top_down(P, n):
      for j in range(2, n + 1):
          # Up-heap bubbling da P[j]
          i = j
          while i > 1 and P[i // 2].key > P[i].key:
              swap(P[i], P[i // 2])
              i = i // 2
  ```
- **Complessità:** Al caso pessimo la complessità è **$\Theta(n \log n)$**.
  $$T(n) = \sum_{j=2}^{n} O(\log j) = \Theta(n \log n)$$

---

### 2. Costruzione Bottom-Up (Algoritmo di Floyd)
- **Idea:** Parte dai nodi interni più profondi (da $j = \lfloor n/2 \rfloor$ a scendere fino alla radice $j = 1$) ed esegue il [[Down-Heap Bubbling]] su ciascun sottoalbero.
- **Algoritmo:**
  ```python
  def build_heap_bottom_up(P, n):
      for j in range(n // 2, 0, -1):
          # Down-heap bubbling da P[j]
          down_heap(P, j, n)
  ```

#### Analisi della Complessità Lineare $O(n)$
Per ogni nodo al livello $i$ (con $0 \le i \le h$), il costo del down-heap bubbling è proporzionale all'altezza del sottoalbero $h - i$. Vi sono al più $2^i$ nodi al livello $i$. La somma totale dei costi è:

$$T(n) = O\left( \sum_{i=0}^{h-1} 2^i (h - i) \right)$$

Sostituendo $\ell = h - i$, la sommatoria diventa:

$$\sum_{\ell=1}^{h} \ell \, 2^{h-\ell} = 2^h \sum_{\ell=1}^{h} \frac{\ell}{2^\ell}$$

Poiché la serie arithmetico-geometrica converge a una costante ($\sum_{\ell=1}^{\infty} \frac{\ell}{2^\ell} = 2$) e sapendo che $2^h \le n$, si ricava che la complessità totale della costruzione bottom-up è **$\Theta(n)$**.

---

### Confronto Top-Down vs Bottom-Up

| Proprietà | Top-Down | Bottom-Up |
| :--- | :--- | :--- |
| **Operazione base** | [[Up-Heap Bubbling]] | [[Down-Heap Bubbling]] |
| **Direzione** | Dalla radice alle foglie (da $j=2$ a $n$) | Dalle foglie alla radice (da $j=\lfloor n/2 \rfloor$ a $1$) |
| **Complessità Temporale** | $\Theta(n \log n)$ | **$\Theta(n)$** |
| **Spazio Ausiliario** | $O(1)$ (In-place) | $O(1)$ (In-place) |

## 5. Algoritmi di Ordinamento basati su Coda di Priorità

Un generico algoritmo **`PriorityQueueSort`** si articola in due fasi:
1. **Fase A:** Inserimento delle $n$ chiavi nella coda di priorità $P$.
2. **Fase B:** Estrazione sequenziale delle chiavi ordinate tramite $n$ chiamate a `removeMin()`.

```python
def priority_queue_sort(S):
    P = PriorityQueue()
    for item in S:
        P.insert(item.key, item.value)
    
    i = 0
    while not P.is_empty():
        S[i] = P.remove_min()
        i += 1
```

### Relazione con gli Algoritmi di Ordinamento Classici

1. **[[SelectionSort]]:** Implementa `PriorityQueueSort` usando una lista **non ordinata**.
   - Fase A: $\Theta(n)$
   - Fase B: $\sum_{i=1}^{n} \Theta(i) = \Theta(n^2)$
   - Complessità totale: **$\Theta(n^2)$**.

2. **[[InsertionSort]]:** Implementa `PriorityQueueSort` usando una lista **ordinata**.
   - Fase A: $\sum_{i=1}^{n} \Theta(i) = \Theta(n^2)$
   - Fase B: $\Theta(n)$
   - Complessità totale: **$\Theta(n^2)$**.

3. **[[HeapSort]]:** Implementa `PriorityQueueSort` utilizzando un **Heap**.
   - Fase A: $O(n \log n)$ (o $\Theta(n)$ con costruzione Bottom-Up).
   - Fase B: $n \times O(\log n) = \Theta(n \log n)$.
   - Complessità totale: **$\Theta(n \log n)$** in spazio **In-place** $O(1)$.

## 6. Algoritmo Avanzato: Selezione dei primi $m$ Minimi

Dato un Heap $P$ con $n$ elementi e un intero $m < n$, è possibile trovare ed estrarre i primi $m$ elementi più piccoli in tempo **$O(m \log m)$** (indipendente da $n$) senza modificare l'heap originale.

### Idea dell'Algoritmo
Si utilizza un'ulteriore coda di priorità ausiliaria $Q$ che memorizza le coppie $\langle \text{chiave}, \text{indice}\rangle$.

```python
def get_m_minima(P, n, m):
    Q = MinPriorityQueue()
    S = []
    
    # Inserisce la radice dell'heap P in Q
    Q.insert(P[1].key, 1)
    
    for i in range(1, m + 1):
        key, j = Q.remove_min()
        S.append(P[j])
        
        # Inserisce in Q i figli di P[j] presenti nell'heap originale
        left_child = 2 * j
        right_child = 2 * j + 1
        
        if left_child <= n:
            Q.insert(P[left_child].key, left_child)
        if right_child <= n:
            Q.insert(P[right_child].key, right_child)
            
    return S
```

### Analisi della Complessità
- La dimensione massima di $Q$ durante le $m$ iterazioni non supera mai $2m + 1 \in O(m)$.
- Ogni operazione su $Q$ richiede tempo $O(\log |Q|) = O(\log m)$.
- Pertanto, l'estrazione dei primi $m$ elementi richiede tempo **$O(m \log m)$** e spazio ausiliario **$O(m)$**
