# Analisi della Complessità Computazionale

> [!info] Sintesi
> Questa nota raccoglie le dimostrazioni matematiche e l'analisi formale di **[[Complessità Computazionale]]** per le principali strutture dati e algoritmi. Vengono analizzati i limiti superiori e inferiori per le operazioni su **[[Heap]]** (inclusa la dimostrazione della costruzione **Bottom-up** in tempo lineare $O(n)$), la ricerca e il bilanciamento su **[[Albero Binario di Ricerca|BST]]**, **[[Multi-Way Search Tree]]** e **[[(2,4)-Tree]]**, nonché l'analisi dettagliata tramite **[[Albero della Ricorsione]]** per gli algoritmi di ordinamento (**[[MergeSort]]**, **[[QuickSort]]**, **[[InsertionSort]]** con il calcolo delle inversioni, **[[BucketSort]]** e **[[RadixSort]]**).

## 1. Code di Priorità e Heap

### 1.1 Inserimento (`insert`) e Up-Heap Bubbling

L'algoritmo di inserimento in un Heap aggiunge l'elemento in ultima posizione e ripristina la proprietà d'ordine risalendo l'albero:

```python
def insert(P, e):
    last = last + 1
    P[last] = e
    i = last
    # Up-heap bubbling
    while i > 1 and P[i // 2].key > P[i].key:
        swap(P[i], P[i // 2])
        i = i // 2
    return e
```

#### Dimostrazione della Complessità $\Theta(\log n)$
- **Limite Superiore $O(h)$:** L'algoritmo è dominato dal ciclo `while`, che compie al più $h$ iterazioni, dove $h$ è l'altezza dell'heap. Quindi $T(n) = O(h)$.
- **Limite Inferiore $\Omega(h)$:** Esiste un'istanza critica (es. l'inserimento di una chiave strettamente minore di tutte quelle presenti nell'heap) per cui il nodo risale fino alla radice, eseguendo esattamente $h$ scambi. Quindi $T(n) = \Omega(h)$.
- **Conclusione:** Poiché per un albero binario completo $h = \lfloor \log_2 n \rfloor$, la complessità dell'inserimento è:
  $$\mathbf{T(n) = \Theta(h) = \Theta(\log n)}$$

---

### 1.2 Estrazione del Minimo (`removeMin`) e Down-Heap Bubbling

L'algoritmo salva la radice, la sostituisce con l'elemento in posizione `last` e fa scendere il nodo applicando il rilassamento verso il basso:

```python
def remove_min(P):
    min_entry = P[1]
    P[1] = P[last]
    last = last - 1
    i = 1
    # Down-heap bubbling
    while 2 * i <= last:
        j = min_child_index(P, i, last)
        if P[i].key > P[j].key:
            swap(P[i], P[j])
            i = j
        else:
            break
    return min_entry
```

#### Dimostrazione della Complessità $\Theta(\log n)$
- **Limite Superiore $O(h)$:** Il ciclo `while` esegue al massimo $h$ iterazioni lungo la profondità dell'albero $\implies O(h)$.
- **Limite Inferiore $\Omega(h)$:** Esiste un'istanza di caso pessimo (es. l'elemento spostato dalla radice ha una chiave maggiore di tutti i nodi nell'heap) in cui si scende fino al livello delle foglie $\implies \Omega(h)$.
- **Conclusione:** 
  $$\mathbf{T(n) = \Theta(h) = \Theta(\log n)}$$

---

### 1.3 Costruzione dell'Heap Top-Down

L'algoritmo inserisce progressivamente gli elementi da $j = 2$ ad $n$ eseguendo l'**[[Up-Heap Bubbling]]**:

```python
def build_heap_top_down(P, n):
    for j in range(2, n + 1):
        up_heap(P, j)
```

#### Analisi Matematica e Sommatoria
All'iterazione $j$-esima, l'[[Up-Heap Bubbling]] viene eseguito su un heap parziale di $j-1$ elementi, con altezza $\lfloor \log_2 j \rfloor$.

1. **Sommatoria della Complessità:**
   $$T(n) = \sum_{j=2}^{n} \Theta(\log j) = \sum_{j=1}^{n} \log j$$

2. **Dimostrazione del Limite Superiore $O(n \log n)$:**
   $$\sum_{j=1}^{n} \log j \le \sum_{j=1}^{n} \log n = n \log n \implies \mathbf{O(n \log n)}$$

3. **Dimostrazione del Limite Inferiore $\Omega(n \log n)$:**
   $$\sum_{j=1}^{n} \log j \ge \sum_{j=\lfloor n/2 \rfloor}^{n} \log j \ge \sum_{j=\lfloor n/2 \rfloor}^{n} \log \left(\frac{n}{2}\right) = \frac{n}{2} (\log n - 1) \implies \mathbf{\Omega(n \log n)}$$

4. **Conclusione:** La costruzione Top-down ha una complessità di:
   $$\mathbf{T(n) = \Theta(n \log n)}$$

---

### 1.4 Costruzione dell'Heap Bottom-Up (Algoritmo di Floyd)

La costruzione **Bottom-up** parte dai nodi interni a livello $h-1$ scendendo fino alla radice e applica il **[[Down-Heap Bubbling]]**:

```python
def build_heap_bottom_up(P, n):
    for j in range(n // 2, 0, -1):
        down_heap(P, j, n)
```

#### Dimostrazione della Complessità Lineare $O(n)$
Analizziamo il costo sommando i contributi per ciascun livello $i$ dell'albero (da $i = 0$ a $h-1$):
- Al livello $i$, ci sono al più $2^i$ nodi.
- Il costo del Down-Heap bubbling per un nodo al livello $i$ è limitato dall'altezza del sottoalbero: $E \le (h - i)$.

La sommatoria totale del costo è:
$$T(n) \le \sum_{i=0}^{h-1} 2^i (h - i)$$

> [!abstract] Dimostrazione Formale per Induzione (Claim)
> **Claim:** $\sum_{i=0}^{h-1} 2^i (h - i) \le 3 n \in O(n)$, dove $n = 2^h - 1$.
> 
> - **Caso Base ($h = 1$):**
>   Per $h = 1$, $n = 2^1 - 1 = 1$.
>   $$\sum_{i=0}^{0} 2^0 (1 - 0) = 1 \le 3(1) = 3 \quad \text{(Verificato)}$$
> 
> - **Passo Induttivo ($h \to h+1$):**
>   Ipotizziamo vera la proprietà per $h$. Per un albero di altezza $h+1$:
>   $$\sum_{i=0}^{h} 2^i (h + 1 - i) = (h + 1) + 2 \sum_{i=0}^{h-1} 2^i (h - i)$$
>   Applicando l'ipotesi induttiva, la sommatoria risulta delimitata superiormente da $3 \cdot 2^{h+1} - 3 = 3n$.
> 
> **Conclusione:** La costruzione dell'heap Bottom-up ha complessità temporale **$\mathbf{\Theta(n)}$**.

## 2. Mappe, Dizionari e Alberi di Ricerca

### 2.1 Ricerca in Alberi Binari di Ricerca (`TreeSearch`)

```python
def tree_search(T, v, k):
    if T.is_external(v) or v.element.key == k:
        return v
    if k < v.element.key:
        return tree_search(T, T.left(v), k)
    else:
        return tree_search(T, T.right(v), k)
```

#### Analisi della Complessità
- **[[Albero della Ricorsione]]:** L'algoritmo segue un singolo cammino dalla radice verso le foglie. Il numero di invocazioni ricorsive è limitato dall'altezza dell'albero $h$.
- Il lavoro svolto in ciascun nodo (esclusa la chiamata ricorsiva) è $\Theta(1)$.
- **Complessità Totale:** 
  $$\mathbf{T(n) = \Theta(h + 1)}$$
- Le operazioni del dizionario `get`, `put` e `remove` sono tutte dominate da `TreeSearch`, con complessità $\Theta(h + 1)$ (pari a $O(\log n)$ nel caso bilanciato e $\Theta(n)$ nel caso pessimo degenere).

---

### 2.2 Ricerca in Multi-Way Search Tree (`MWTreeSearch`)

In un **[[Multi-Way Search Tree]]**, un nodo $v$ contiene $d-1$ entry con $d$ figli.

```python
def mw_tree_search(T, v, k):
    if T.is_external(v):
        return v
    # Cerca k tra le entry del nodo v (k1 < k2 < ... < kd-1)
    # Trova l'indice i tale che ki-1 < k <= ki
    if k == k_i:
        return v
    return mw_tree_search(T, child(v, i), k)
```

#### Analisi della Complessità
- Sia $d_{max}$ il numero massimo di figli di un qualsiasi nodo in $T$.
- Ad ogni nodo del cammino (lungo al più $h$), viene eseguita una ricerca lineare tra le $d-1$ chiavi locali in tempo $O(d_{max})$.
- **Complessità Totale:**
  $$\mathbf{T(n) = O(d_{max} \cdot h)}$$

### 2.3 Operazione di `Split` nei (2,4)-Tree

Quando l'inserimento genera un 5-node (overflow), viene invocata la procedura ricorsiva **[[Split]]**:

```python
def split(T, v):
    if v.is_root():
        # Crea una nuova radice contenente e3 e con u' e u'' come figli
        return
    v_parent = T.parent(v)
    # Inserisce e3 nel padre e collega u' e u''
    if v_parent.is_5_node():
        split(T, v_parent) # Chiamata ricorsiva
```

#### Analisi della Complessità
- Ogni passo di `Split` esegue una quantificazione costante di riallocazione dei puntatori e scambi: costo $\Theta(1)$ locale.
- La chiamata ricorsiva risale lungo l'altezza dell'albero dal nodo foglia verso la radice ($h \le \log_2(n+1)$).
- **Complessità Totale:**
  $$\mathbf{T(n) = O(h) = \Theta(\log n)}$$

## 3. Algoritmi di Ordinamento

### 3.1 MergeSort

```python
def merge_sort(S):
    n = len(S)
    if n <= 1:
        return S
    mid = n // 2
    S1 = merge_sort(S[:mid])
    S2 = merge_sort(S[mid:])
    return merge(S1, S2)
```

#### Analisi con l'Albero della Ricorsione
1. **Caso ideale ($n = 2^d$, con $d = \log_2 n$):**
   - L'altezza dell'albero della ricorsione è $d = \log_2 n$.
   - Al livello $i \in [0, d]$, vi sono $2^i$ nodi che operano su istanze di dimensione $n / 2^i$.
   - Il costo locale della fusione `Merge` a ciascun nodo interno del livello $i$ è $O(n / 2^i)$.
   - Il costo per livello è:
     $$\text{Costo Level } i = 2^i \cdot O\left(\frac{n}{2^i}\right) = \Theta(n)$$
   - Sommando su tutti i $d = \log_2 n$ livelli:
     $$T(n) = \sum_{i=0}^{d-1} \Theta(n) = \mathbf{\Theta(n \log n)}$$

2. **Caso generale ($n \in [2^d, 2^{d+1}]$):**
   - La somma dei costi al livello $i$ è proporzionale a $\Theta(2^i \cdot (n / 2^i)) = \Theta(n)$.
   - **Complessità Globale:** $\mathbf{T(n) = \Theta(n \log n)}$ sia al caso migliore, medio che pessimo.

### 3.2 Partition e QuickSort In-Place

#### Complessità della Procedura `Partition`
```python
def partition(S, a, b):
    p = S[b]
    l = a
    r = b - 1
    while l <= r:
        while l <= r and S[l] <= p:
            l += 1
        while l <= r and S[r] >= p:
            r -= 1
        if l < r:
            S[l], S[r] = S[r], S[l]
    S[l], S[b] = S[b], S[l]
    return l
```
- Ad ogni iterazione dei cicli interni, l'indice $l$ viene incrementato o $r$ viene decrementato.
- Il numero totale di confronti ed incrementi/decrementi è strettamente pari al numero di elementi del sottovettore: $(b - a) + 1$.
- **Complessità di `Partition`:** $\mathbf{\Theta((b - a) + 1)}$.

---

#### Complessità del Caso Pessimo di `QuickSortInPlace`
Nel caso pessimo (es. array già ordinato in senso crescente o decrescente), il pivot selezionato isola un solo elemento alla volta.
- L'albero della ricorsione degenera in una catena di altezza $n-1$.
- Il costo del nodo al livello $i$ è $O(n - i)$.
- Sommando i costi:
  $$T(n) = \sum_{i=0}^{n-1} O(n - i) = \mathbf{\Theta(n^2)}$$

### 3.3 InsertionSort e Analisi Fine delle Inversioni

```python
def insertion_sort(S):
    n = len(S)
    for i in range(1, n):
        current = S[i]
        j = i - 1
        while j >= 0 and S[j] > current:
            S[j + 1] = S[j]
            j -= 1
        S[j + 1] = current
```

#### 1. Analisi Standard (Caso Pessimo e Medio)
- Il ciclo esterno `for` esegue $n-1$ iterazioni.
- Il ciclo interno `while` esegue al più $i$ operazioni al passo $i$-esimo.
- **Caso Pessimo (Array ordinato al contrario):**
  $$T(n) = \sum_{i=1}^{n-1} O(i) = \frac{n(n-1)}{2} \in \mathbf{\Theta(n^2)}$$

---

#### 2. Analisi Fine basata sul Numero di Inversioni $K$

> [!abstract] Definizione di Inversione
> Una coppia di indici $(i, j)$ costituisce una **[[Inversione]]** se $0 \le i < j < n$ e $S[i] > S[j]$.

- Ad ogni esecuzione del corpo del ciclo `while`, un elemento viene scambiato con il suo adiacente, **eliminando esattamente un'inversione**.
- La somma di tutte le iterazioni del ciclo `while` durante l'intera esecuzione dell'algoritmo è esattamente pari al numero totale di inversioni $K$ presenti nell'array iniziale.
- Il ciclo `for` esegue comunque $\Theta(n)$ controlli di test.
- **Complessità Fine:**
  $$\mathbf{T(n) = \Theta(n + K)}$$
- *Corollario:* Per array **quasi ordinati** dove $K = O(n)$, `InsertionSort` viene eseguito in tempo **lineare $\Theta(n)$**.

### 3.4 BucketSort e RadixSort

#### Complessità di BucketSort
```python
def bucket_sort(S, N):
    B = [[] for _ in range(N)]
    for entry in S:
        B[entry.key].append(entry)
    
    S_sorted = []
    for i in range(N):
        while not B[i].is_empty():
            S_sorted.append(B[i].pop(0))
    return S_sorted
```
- Distribuzione nei bucket (primo ciclo): $\Theta(n)$.
- Estrazione dai $N$ bucket (secondo ciclo): $\Theta(N + n)$.
- **Complessità Totale:**
  $$\mathbf{T(n) = \Theta(n + N)}$$

---

#### Complessità di RadixSort
`RadixSort` ordina chiavi composte da $d$ cifre eseguendo $d$ chiamate a uno stabilizzatore `BucketSort` (su cifre nell'intervallo $[0, N-1]$):

```python
def radix_sort(S, d, N):
    for i in range(d):
        S = bucket_sort_by_digit(S, digit_index=i, N=N)
    return S
```

- Ciascuno dei $d$ passaggi ha complessità $\Theta(n + N)$.
- **Complessità Totale:**
  $$\mathbf{T(n) = \Theta(d(n + N))}$$
- Se $d = O(1)$ e $N = O(n)$, la complessità è strettamente **lineare $\Theta(n)$**.
