# Alberi, Alberi Binari e Heap

> [!info] Sintesi
> Questa nota raccoglie la teoria e la formalizzazione matematico-algoritmica riguardante la struttura dati degli **alberi**. Vengono analizzati gli [[Albero Generale|alberi generali]] (definizioni, relazioni gerarchiche, metriche di profondità ed altezza e tecniche di visita), gli [[Albero Binario|alberi binari]] con le relative proprietà strutturali e dimostrazioni induttive, e infine gli [[Albero Binario Completo|alberi binari completi]] con l'implementazione della struttura dati [[Heap]] tramite vettori e indicizzazione per [[Level Numbering]].

---

## 1. Alberi Generali: Definizioni e Proprietà

### Definizione di Albero Radicato
Un **[[Albero Radicato]]** $T$ è una collezione finita di nodi organizzati secondo una struttura gerarchica di tipo padre-figlio. Se non è vuoto, soddisfa le seguenti proprietà:
1. Esiste un nodo distinto chiamato **[[Radice]]** $r \in T$.
2. Per ogni nodo $v \neq r$, existe un unico nodo $u \in T$ detto **[[Padre]]** di $v$ ($u = \text{parent}(v)$), e $v$ è detto **[[Figlio]]** di $u$.
3. Risalendo di padre in padre a partire da qualsiasi nodo $v$, si giunge sempre univocamente alla radice $r$.

#### Definizione Ricorsiva
Un albero radicato $T$ è una collezione di nodi partizionata come segue:
$$T = \{r\} \cup T_1 \cup T_2 \cup \dots \cup T_k \quad (k \ge 0)$$
dove $r$ è la radice di $T$ e ogni $T_i$ ($1 \le i \le k$) è un albero non vuoto (detto sottoalbero) la cui radice $u_i$ è figlia di $r$.

---

### Terminologia e Relazioni tra Nodi
- **[[Antenati]]:** Un nodo $u$ è antenato di $v$ se $u = v$ oppure $u$ è antenato del padre di $v$.
- **[[Discendenti]]:** Un nodo $v$ è discendente di $u$ se $u$ è antenato di $v$.
- **[[Nodo Interno]]:** Un nodo con almeno un figlio ($\text{numChildren}(v) > 0$).
- **[[Nodo Esterno]] (o [[Foglia]]):** Un nodo privo di figli ($\text{numChildren}(v) = 0$).
- **[[Fratelli]]:** Nodi che condividono lo stesso padre.
- **[[Albero Ordinato]]:** Un albero in cui è definito un ordinamento lineare ben preciso tra i figli di ciascun nodo.

---

### Metriche di Posizione e Dimensione

#### Profondità (Depth)
La **[[Profondità di un Nodo]]** $v \in T$ ($\text{depth}(v)$) è il numero di antenati propri di $v$ (escluso $v$ stesso):
$$\text{depth}(v) = \begin{cases} 0 & \text{se } v \text{ è la radice } r \\ 1 + \text{depth}(\text{parent}(v)) & \text{se } v \neq r \end{cases}$$

- **[[Livello di un Albero]] $i$:** Insieme di tutti i nodi a profondità $i$ ($\{v \in T : \text{depth}(v) = i\}$).

#### Altezza (Height)
L'**[[Altezza di un Nodo]]** $v \in T$ ($\text{height}(v)$) è la lunghezza del cammino più lungo da $v$ ad una foglia del sottoalbero $T_v$:
$$\text{height}(v) = \begin{cases} 0 & \text{se } v \text{ è una foglia} \\ 1 + \max_{w \in \text{children}(v)} (\text{height}(w)) & \text{se } v \text{ è nodo interno} \end{cases}$$

L'**[[Altezza di un Albero]]** $T$ ($\text{height}(T)$) corrisponde all'altezza della radice $r$, ovvero alla massima profondità tra le sue foglie:
$$\text{height}(T) = \text{height}(r) = \max_{v \in T : v \text{ è foglia}} (\text{depth}(v))$$

> [!note] Dimostrazione dell'equivalenza dell'Altezza
> La proprietà $\text{height}(T) = \max_{v \in T : v \text{ foglia}} (\text{depth}(v))$ si dimostra per **[[Dimostrazione per Induzione|induzione]]** sul numero di nodi $n$ dell'albero:
> - **Caso Base ($n=1$):** L'albero ha solo la radice $r$. $\text{height}(r) = 0$ e $\text{depth}(r) = 0$. La tesi è verificata.
> - **Passo Induttivo ($n > 1$):** La radice $r$ ha $k \ge 1$ sottoalberi $T_1, \dots, T_k$ radicati nei figli $u_1, \dots, u_k$. Per ipotesi induttiva la proprietà vale per ciascun sottoalbero di dimensione inferiore. Riscrivendo l'altezza come $1 + \max \text{height}(u_i)$ e sostituendo la profondità relativa, si ricava la coincidenza con la profondità massima globale.

## 2. ADT Albero e Algoritmi Fondamentali

### Interfaccia ADT Tree
L'**[[Abstract Data Type|ADT]]** per un albero generale ad arità arbitraria espone i seguenti metodi essenziali:

```java
public interface Tree<E> extends Iterable<E> {
    Position<E> root();
    Position<E> parent(Position<E> p) throws IllegalArgumentException;
    Iterable<Position<E>> children(Position<E> p) throws IllegalArgumentException;
    int numChildren(Position<E> p) throws IllegalArgumentException;
    boolean isInternal(Position<E> p) throws IllegalArgumentException;
    boolean isExternal(Position<E> p) throws IllegalArgumentException;
    boolean isRoot(Position<E> p) throws IllegalArgumentException;
    int size();
    boolean isEmpty();
    Iterator<E> iterator();
    Iterable<Position<E>> positions();
}
```

---

### Algoritmi per il Calcolo delle Metriche

#### 1. Calcolo della Profondità di un Nodo

##### Algoritmo Ricorsivo (`depth`)
```python
def depth(T, v):
    if T.is_root(v):
        return 0
    else:
        return 1 + depth(T, T.parent(v))
```
- **[[Complessità Computazionale|Complessità]]:** $\Theta(d + 1)$, dove $d = \text{depth}(v)$. L'albero della ricorsione consiste in un cammino singolo di $d + 1$ nodi, con lavoro $O(1)$ per chiamata.
- **Relazione di ricorrenza:**
  $$t(d) = \begin{cases} c_1 & \text{se } d = 0 \\ t(d - 1) + c_2 & \text{se } d > 0 \end{cases}$$

##### Algoritmo Iterativo (`iter-depth`)
```python
def iter_depth(T, v):
    d = 0
    while not T.is_root(v):
        v = T.parent(v)
        d += 1
    return d
```
- **Complessità:** $\Theta(d + 1)$ in tempo e $O(1)$ in spazio ausiliario.

#### 2. Calcolo dell'Altezza di un Sottoalbero (`height`)
```python
def height(T, v):
    h = 0
    for w in T.children(v):
        h = max(h, 1 + height(T, w))
    return h
```
- **Complessità:** $\Theta(n_v)$, dove $n_v$ è il numero di nodi del sottoalbero $T_v$ radicato in $v$.
  - L'algoritmo viene invocato esattamente una volta per ogni nodo $u \in T_v$.
  - Il lavoro non ricorsivo in $u$ è $\Theta(c_u + 1)$, dove $c_u$ è il numero di figli di $u$.
  - Sum del costo: $\sum_{u \in T_v} \Theta(c_u + 1) = \Theta\left(\sum c_u + n_v\right) = \Theta(n_v - 1 + n_v) = \Theta(n_v)$.

---

### Visite di Alberi Generali

Una **[[Visita di un Albero]]** è un algoritmo che accede sistematicamente a tutti i nodi dell'albero ed esegue un'operazione ("visita") su ciascuno di essi.

#### Visita in Preorder (Pre-ordine)
Nella **[[Visita in Preorder]]**, si visita prima la radice (o il nodo corrente) e successivamente si visitano ricorsivamente i sottoalberi radicati nei figli (da sinistra a destra se l'albero è ordinato).

```python
def preorder(T, v):
    visit(v)
    for w in T.children(v):
        preorder(T, w)
```
- **Ordine di visita:** Padre $\rightarrow$ Figli.
- **Complessità:** $\Theta(n)$ per un albero di $n$ nodi (assumendo che l'operazione `visit(v)` richieda tempo $O(1)$).

#### Visita in Postorder (Post-ordine)
Nella **[[Visita in Postorder]]**, si visitano prima ricorsivamente i sottoalberi radicati nei figli e solo infine si visita il nodo corrente (padre).

```python
def postorder(T, v):
    for w in T.children(v):
        postorder(T, w)
    visit(v)
```
- **Ordine di visita:** Figli $\rightarrow$ Padre.
- **Complessità:** $\Theta(n)$.
- **Applicazione:** Il calcolo dell'altezza `height(T, v)` è un esempio pratico di visita in postorder, in quanto l'altezza del padre viene determinata solo dopo aver calcolato le altezze di tutti i suoi figli.

## 3. Alberi Binari

### Definizione e Proprietà
Un **[[Albero Binario]]** $T$ è un albero ordinato che soddisfa le seguenti condizioni:
1. Ogni nodo interno ha **al più 2 figli** ($\text{numChildren}(v) \le 2$).
2. Ogni figlio è etichettato univocamente come **figlio sinistro** o **figlio destro**.
3. Il figlio sinistro precede il figlio destro nell'ordinamento dei figli.

#### Interfaccia ADT BinaryTree
```java
public interface BinaryTree<E> extends Tree<E> {
    Position<E> left(Position<E> p);
    Position<E> right(Position<E> p);
    Position<E> sibling(Position<E> p);
}
```

---

### Alberi Binari Propri
Un **[[Albero Binario Proprio]]** (o pieno) è un albero binario in cui ogni nodo interno ha **esattamente 2 figli**.

#### Relazioni Fondamentali tra i Parametri
Dato un albero binario proprio non vuoto con:
- $n$: numero totale di nodi
- $m$: numero di foglie (nodi esterni)
- $i = n - m$: numero di nodi interni
- $h$: altezza dell'albero

Valgono le seguenti proprietà matematiche stabili:

1. **Relazione Nodi Interni - Foglie:**
   $$m = (n - m) + 1 \implies n = 2m - 1 \quad \text{e} \quad i = m - 1$$
2. **Relazione Altezza - Foglie:**
   $$h + 1 \le m \le 2^h$$
3. **Relazione Altezza - Nodi Interni:**
   $$h \le n - m \le 2^h - 1$$
4. **Relazione Altezza - Nodi Totali:**
   $$2h + 1 \le n \le 2^{h+1} - 1$$
5. **Relazione Nodi Totali - Altezza:**
   $$\log_2(n + 1) - 1 \le h \le \frac{n - 1}{2}$$

---

### Dimostrazioni per Induzione

#### Dimostrazione della Relazione $m = (n - m) + 1$
Si procede per **[[Dimostrazione per Induzione|induzione]]** sull'altezza $h$ dell'albero:
- **Caso Base ($h = 0$):** L'albero ha solo la radice ($n = 1$, $m = 1$, nodi interni $n - m = 0$).
  $$m = 1 \quad \text{e} \quad (n - m) + 1 = 0 + 1 = 1 \implies \text{Verificato.}$$
- **Passo Induttivo ($h \ge 0$):** Supponiamo vera la tesi per ogni albero proprio di altezza $h' \le h$. Sia $T$ di altezza $h + 1$. La radice ha due sottoalberi $T_1$ e $T_2$ con $m_1, m_2$ foglie e $n_1, n_2$ nodi totali.
  $$m = m_1 + m_2$$
  $$n = n_1 + n_2 + 1 \implies (n - m) = (n_1 - m_1) + (n_2 - m_2) + 1$$
  Applicando l'ipotesi induttiva su $T_1$ e $T_2$ ($m_1 = n_1 - m_1 + 1$ e $m_2 = n_2 - m_2 + 1$):
  $$m = m_1 + m_2 = (n_1 - m_1 + 1) + (n_2 - m_2 + 1) = (n_1 - m_1 + n_2 - m_2 + 1) + 1 = (n - m) + 1 \quad \square$$

#### Dimostrazione della disuguaglianza $m \le 2^h$
- **Caso Base ($h = 0$):** $m = 1 \le 2^0 = 1$.
- **Passo Induttivo ($h \ge 0$):** Per un albero di altezza $h + 1$, i due sottoalberi $T_1$ e $T_2$ hanno altezze $h_1, h_2 \le h$.
  $$m = m_1 + m_2 \le 2^{h_1} + 2^{h_2} \le 2^h + 2^h = 2 \cdot 2^h = 2^{h+1} \quad \square$$

---

### Visita Inorder (In-ordine / Simmetrica)

Oltre a preorder e postorder, negli alberi binari è definita la **[[Visita Inorder]]**:

```python
def inorder(T, v):
    if T.left(v) is not None:
        inorder(T, T.left(v))
    visit(v)
    if T.right(v) is not None:
        inorder(T, T.right(v))
```

- **Ordine di visita:** Figlio Sinistro $\rightarrow$ Padre $\rightarrow$ Figlio Destro.
- **Complessità:** $\Theta(n)$.
- **Applicazione fondamentale:** Negli **[[Albero Binario di Ricerca|Alberi Binari di Ricerca (BST)]]**, la visita inorder esplora e restituisce i valori delle chiavi memorizzate in ordine strettamente crescente.

## 4. Alberi Binari Completi e Heap

### Definizione di Albero Binario Completo
Un **[[Albero Binario Completo]]** di altezza $h$ è un albero binario in cui:
1. Per ogni livello $i$ con $0 \le i \le h - 1$, il livello contiene esattamente $2^i$ nodi (saturazione massima).
2. Al livello $h$, i nodi sono riempiti contiguamente **da sinistra a destra**.

```
        (1)             <- Livello 0 (1 nodo)
       /   \
     (2)   (3)          <- Livello 1 (2 nodi)
    /  \   /
  (4)  (5)(6)           <- Livello 2 (3 nodi, riempiti da sx a dx)
```

#### Relazione tra Nodi e Altezza
Un albero binario completo con $n$ nodi ha un'altezza strettamente contenuta:
$$h = \lfloor \log_2 n \rfloor$$

---

### Struttura Dati Heap

Un **[[Heap]]** (nello specifico Min-Heap) è un albero binario completo i cui nodi memorizzano coppie $\langle \text{chiave}, \text{valore} \rangle$ che soddisfano la **[[Heap-Order Property]]**:

> [!abstract] Heap-Order Property (Min-Heap)
> Per ogni nodo $v \neq r$ con padre $u = \text{parent}(v)$:
> $$\text{key}(u) \le \text{key}(v)$$
> Di conseguenza, la radice $r$ contiene sempre l'elemento con **chiave minima** dell'intero Heap ($\text{min}() \in \Theta(1)$).

*(Nota: In un **Max-Heap**, la relazione è invertita: $\text{key}(u) \ge \text{key}(v)$, e la radice contiene la chiave massima).*

- **[[Last Node]] di un Heap:** È il nodo situato più a destra al livello più profondo $h$.

---

### Realizzazione di un Heap tramite Array e Level Numbering

Gli alberi binari completi consentono una rappresentazione in memoria compatta mediante array $P$ senza l'uso di puntatori espliciti, sfruttando la numerazione per livelli (**[[Level Numbering]]**).

```
Indice Array:  [0] | [1] | [2] | [3] | [4] | [5] | [6]
Elementi:       -  |  r  |  v1 |  v2 |  v3 |  v4 |  v5
```

#### Regole di Mappatura Indici (1-based indexing)
- **Radice:** Memorizzata in $P[1]$.
- **Figlio Sinistro** di $P[i]$: Posizionato in $P[2i]$.
- **Figlio Destro** di $P[i]$: Posizionato in $P[2i + 1]$.
- **Padre** di $P[i]$: Posizionato in $P[\lfloor i / 2 \rfloor]$.
- **Last Node:** Corrisponde esattamente a $P[n]$, dove $n$ è il numero totale di elementi.

> [!warning] Efficienza Spaziale vs Sbilanciamento
> La rappresentazione tramite *Level Numbering* è eccezionalmente **space-efficient** per alberi completi (zero spazio sprecato). Tuttavia, se applicata ad alberi generici fortemente sbilanciati (es. alberi degeneri a catena), gli indici crescono fino a $2^h$, richiedendo uno spazio esponenziale $O(2^n)$ privo di utilizzi pratici.

## 5. Algoritmi Notabili ed Esercizi Teorici

### Successore in Preorder (`preorderNext`)
Dato un nodo $v$ in un albero binario proprio $T$, l'algoritmo determina il nodo successivo nella visita preorder:

```python
def preorder_next(T, v):
    # Se v è nodo interno, il successore è il figlio sinistro
    if T.is_internal(v):
        return T.left(v)
    
    # Se v è foglia, si risale la catena dei padri
    while not T.is_root(v):
        if v == T.left(T.parent(v)):
            return T.sibling(v)  # Figlio destro del primo antenato valido
        v = T.parent(v)
        
    return None  # v era l'ultimo nodo visitato
```
- **Complessità:** $O(h)$ al caso pessimo per risalita lungo l'altezza dell'albero.

---

### Calcolo di `heightSum`
Calcolare la somma delle altezze di tutti i nodi di un albero binario proprio $T$:

```python
def height_sum_rec(T, v):
    if T.is_external(v):
        return 0, 0  # (altezza di v, somma altezze sottoalbero)
    
    h_left, sum_left = height_sum_rec(T, T.left(v))
    h_right, sum_right = height_sum_rec(T, T.right(v))
    
    h_v = 1 + max(h_left, h_right)
    total_sum = h_v + sum_left + sum_right
    
    return h_v, total_sum

def height_sum(T, v):
    _, total = height_sum_rec(T, v)
    return total
```
- **Complessità:** $\Theta(n_v)$ con visita in postorder ed elaborazione $O(1)$ per nodo.

### Lowest Common Ancestor (LCA)
Il **[[Lowest Common Ancestor]]** $\text{LCA}(v, w)$ di due nodi $v, w \in T$ è l'antenato comune situato alla massima profondità.
- **Algoritmo Basato su Profondità:**
  1. Si calcolano $\text{depth}(v)$ e $\text{depth}(w)$.
  2. Si fa risalire il nodo più profondo fino a portarlo allo stesso livello dell'altro.
  3. Si risale passo-passo da entrambi i nodi finché non coincidono: $v = w = \text{LCA}(v, w)$.
- **Complessità:** $O(h)$.
